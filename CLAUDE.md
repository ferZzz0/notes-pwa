## Project Overview

A notes app as an installable, offline-capable PWA: React 19 + TypeScript + Vite 8. The PWA layer (Workbox service worker + web manifest) is generated by `vite-plugin-pwa`. Deployed via Cloudflare Workers Static Assets, same setup as the sibling project `C:\myGit\zuma-pwa`: every push to `main` of `github.com/ferZzz0/notes-pwa` triggers Cloudflare Workers Builds (`npm run build` + `npx wrangler deploy`, config in [wrangler.jsonc](wrangler.jsonc), serving `dist/` with SPA fallback). Production URL: https://notes-polik.sokolovpk.ru. UI text and code comments are in Russian.

**Cloudflare throttling in Russia (blank page).** The user's ISPs stall connections to Cloudflare's `188.114.96.1` / `188.114.97.1` after ~24 KB: the HTML loads, the JS bundle hangs in pending, the page stays blank. `104.21.46.231` / `172.67.143.35` work. Which pair a client gets is effectively random (checked 2026-10-25):

- The system resolver and Yandex `77.88.8.8` alternate between the good and the bad pair; Google `8.8.8.8` and Cloudflare DoH (browser "Secure DNS", which Chrome/Edge auto-enable when the system DNS is `1.1.1.1`) returned only the bad pair.
- `*.workers.dev` (incl. branch previews `*-notes-pwa.2004s-p.workers.dev`) always resolves to `188.114.x` — never verify there.

So any Russian visitor may randomly get a blank first load; once the SW has precached the app it starts from cache, and a failed update download retries later. Not fixable on the Cloudflare free plan; the real fix is hosting outside Cloudflare (e.g. Yandex Object Storage). **On 2026-10-25 the user decided to stay on Cloudflare for now** — don't re-propose migrating unless they ask or it blocks work.

To verify a deploy, pin a good IP instead of trusting DNS: `curl --resolve notes-polik.sokolovpk.ru:443:104.21.46.231 https://notes-polik.sokolovpk.ru/...`, or launch Edge/Chrome with `--host-resolver-rules="MAP notes-polik.sokolovpk.ru 104.21.46.231"`. A stall at ~24 KB means throttling, not a deploy bug.

## Workflow: always deploy

The user reviews every change on their phone (iPhone) against the deployed site, not locally. So after each finished change, without asking: run `npm run check` and `npm run build`, and if both pass, commit and push to `main` — Cloudflare deploys it. Never push a failing build. Then confirm the new version is live on https://notes-polik.sokolovpk.ru. Remind the user that the installed app picks it up via the «Доступна новая версия» → «Обновить» banner.

## UI

- **The product (user's decisions, 2026-10-25):** an open school notebook whose sheets are INFINITE — you see the top edge of the sheet, and the paper continues forever downward and sideways (left page to the left of the spine, right page to the right). The user "flies" over it (pan, pinch-zoom, inertia); portrait shows one page, landscape the spread; text can be written anywhere on the paper; pages turn with a bending 3D page. Plain paper — NO grid (the user asked to remove it: after a swipe the re-rasterized grid visibly redrew). The manifest has no `orientation`.
- History, so it isn't retried blindly (all in git history): a «Поверните телефон» overlay; a "painted rotation" of the app in portrait (dropped: iOS keyboard/status bar don't rotate, iOS animates between painted and real landscape); portrait read-only / landscape write modes; a finite notebook with one textarea per 170×205 mm page, squared paper and double-tap zoom-to-page (replaced by infinite sheets).
- **World coordinates:** the sheet's top edge is `y = 0` (above it is the desk), the spine is `x = 0`; left page `x < 0`, right page `x ≥ 0`. Text sizes are in world px (40px Caveat, 52px lines).
- **[src/components/Canvas.tsx](src/components/Canvas.tsx)** — the pan/zoom engine, hand-written (no library) for full control over how gestures coexist with text input. Camera `{x, y, scale}` (screen = world·scale + x/y) is written straight to `.canvas-world`'s `transform` (no React re-render per frame). Generic: `home` (start view: world point placed at horizontal centre and `top` screen px below the safe area, `width` of world to fit, `minScale`), `edges` (world `top`/`left`/`right` edges that can't be dragged more than 40% into the screen; absent = infinite that way), `locked`, `background` (screen-space layer under the world), `onFrame`/`onSettle`/`onDoubleTap` callbacks (kept in a ref, so the once-subscribed listeners see fresh props), and a ref handle `goHome(home?)` (Promise; optional explicit target), `visibleRect()`, `panBy()`.
  - Gestures: one pointer drag = pan (after an 8px slop, so taps stay taps) with inertia on release (velocity of the last 100 ms, capped); two pointers = pinch around their midpoint + pan; wheel = pan, Ctrl/⌘+wheel (and Chrome's trackpad pinch) = zoom; Safari's Mac trackpad pinch comes only as `gesture*` events (ignored while touch pointers are active — on iOS they duplicate pointer events, we only `preventDefault` them). A single tap on non-interactive space blurs the focused field (closes the keyboard); a double tap there calls `onDoubleTap(worldPoint)`.
  - Limits: scale 0.12…2.5; `edges` as above; otherwise unbounded. On resize/rotation the world point at the screen centre stays centred; the very first layout is `home` (in `useLayoutEffect`, no flash).
  - `touch-action: none` on `.canvas` AND all descendants — otherwise a scrollable child (a textarea) claims the touch and the browser fires `pointercancel` mid-pan.
  - Pointer capture is taken only once a gesture becomes a pan/pinch, so a plain tap still focuses a textarea. Mouse presses on editable elements are ignored by the canvas (text selection works). Elements with `[data-no-pan]` are ignored entirely.
  - **Performance — the fix for the user's "lags with two fingers" (2026-10-25).** The world is ALWAYS its own compositor layer (`will-change: transform`), so pan/pinch only move/scale a ready bitmap. Camera writes are batched to one `transform` write per animation frame (pinch delivers a move per finger). After the camera settles (200 ms) and only if the scale changed, `settle()` drops/restores `will-change` once so text re-renders crisply. Chromium trace of a 120-move pinch: Paint 346 → 4, RasterTask 2083 → 20 (the old version changed a `--zoom` CSS variable every pinch frame, repainting the whole grid, and toggled the layer at every pause). Don't reintroduce per-frame style changes on the world or `will-change` toggling during gestures; keep big blurred shadows out of the world.
  - Safe-area insets are read from a hidden probe element (`env()` exists only in CSS) and used for `home`.
- **[src/components/Paper.tsx](src/components/Paper.tsx)** — the infinite sheet, drawn in SCREEN space as Canvas's `background`: a sheet (200% screen wide and tall, translated to the top edge's screen y clamped at −1 screen; for `display` `left`/`right` its side edge sits on the spine, clamped the same way), the fold shadow around the spine (300 world px wide via `scaleX(scale)`, one-sided for a single page), and the spine line (hidden for a single page — its edge shadow on the desk shows instead). Notebook feeds it the camera from `onFrame`; all three are `will-change` layers that only get `transform` updates — nothing repaints, so infinity is free. Plain colour only: anything textured here would have to be re-rasterized.
- **[src/components/Notebook.tsx](src/components/Notebook.tsx)** — spreads, writing, page turning, screen overlays:
  - Spread `s` (0-based) = pages `2s+1` | `2s+2`; state is the open PAGE (1-based). Only the current spread is rendered. Each side shows its page number by the spine; the date the spread was first written on (today's date faintly when empty) is on the right side, or on the left side when only it is shown; spread 0's left side has the help text. No staples (user removed them 2026-10-25).
  - **View by orientation (user's decision, 2026-10-25): portrait = ONE page, landscape = the spread** ([src/orientation.ts](src/orientation.ts) `usePortrait()`, `(orientation: portrait)`, desktops included). There is no setting for it (a gear with a «1 | 2» switch existed briefly — git history). One page = `display` `left`/`right`: Paper cuts the sheet at the spine, Canvas gets an edge there (`edges.right = 0` / `left = 0`) and `home` centres that page (850+50 world px wide); double-tap beyond the page's edge flies home instead of writing. While moving between views (`transit`) both sides are drawn and only the top edge applies, so the camera can cross the spine without clamping jumps. The `single` state follows `portrait` one frame later via an effect (transit → `goHome` of the new view). `Canvas.goHome()` re-measures the viewport itself, because the orientation media-query event fires BEFORE ResizeObserver delivers the new size (without that the new home was computed for the old screen). Home places the sheet's top edge 64 screen px down.
  - Left-page texts never cross the spine: created at most at x = −224 and rendered with width `min(640, −x − 24)` (≥ 200).
  - **Writing:** double-tap on paper creates an empty [TextBlock](src/components/TextBlock.tsx) (640 world px wide auto-growing textarea, no chrome) at that point and focuses it. It must be rendered with `flushSync` and focused synchronously inside the pointer handler — otherwise iOS won't open the keyboard. Tap a text to edit; a text left empty is removed on blur. Double-tap on the desk (`y < 0`) flies home. While a text is focused, `keepVisible` pans the camera so the line isn't hidden by the keyboard (uses `visualViewport`, on focus after 350 ms, on input, and on `visualViewport` resize) — unverified on a real iPhone.
  - **Page turning:** round arrow buttons (chevron icons; deliberately light — translucent paper with backdrop blur and muted ink, in dark mode too) in the bottom screen corners (outside the canvas; no "back" on the first page/spread) or ←/→/PageUp/PageDown when not typing. Two pages: by spreads. One page: by pages — to the facing page of the same spread the camera simply flies across the spine; to another spread the sheet turns, then the camera follows to the new page's home. For a turn the camera first flies `home`, then the half-sheet between the spine and the screen edge (world rect from `visibleRect()`) turns 180° around the spine (`FlipSheet`, 900 ms). `.flip-stage` sits at the spine (width 0, `perspective` scaled to the sheet) and holds two cast-shadow layers on the pages beneath (one shrinking toward the spine as the sheet lifts, one growing on the landing side). The sheet is 6 NESTED `preserve-3d` strips: strip 0 (at the spine) rotates 0→180° with an ease-in-out curve, each further strip adds a small relative rotation (`flip-curl-*`: outer edge lifts first, lags when landing, flat at the end) — that's the paper bend. Strips step by `w/6` but are 3 world px wider, so no seams show between the 3D planes. Each strip has a front face (the side being turned) and a back face (`rotateY(180deg)`, `backface-visibility: hidden`; the side that lands opposite); a face shows the WHOLE page (`.flip-face-page`, `width: w`) offset so the strip's slice is visible — front by `left/right: -i·strip` from the edge it's anchored to, back by the opposite edge (the offsets are independent of the overlap). Shading is one gradient over the whole page (darker toward the outer edge), not per strip — per-strip shading looked striped. Page content is the same `PageSide` with a world→page x offset (next: front 0, back +w; prev: front +w, back 0). Gestures are `locked` during the turn. The underlay already shows the destination's other side, and everything is a static "face" during the turn (no textareas). `animationend` on strip 0 itself resolves the turn's promise (`go()` is an async sequence using `flushSync` so Canvas sees new props before each `goHome`). `prefers-reduced-motion` makes the turn instant.
  - «↑ К началу листа» pill appears (on settle) when the top edge is > half a screen above or the home centre > a screen away.
- **Storage** — [src/notes.ts](src/notes.ts): `localStorage` `notes-pwa:spreads` = `{ [spread]: { created?: 'YYYY-MM-DD' local, blocks: [{ id, x, y, text }] } }` (empty blocks are filtered on load; a spread with no text is deleted); `notes-pwa:page` = the open page, restored on launch (falls back to the older `notes-pwa:spread` → page `2s+1`). Migrates once from the previous formats (`notes-pwa:pages` per-page text → a block at the top of that side; `notes-pwa:draft` → page 2) and deletes them. Saved on every keystroke. If notes grow large, move to IndexedDB; the installed iOS app has storage separate from Safari.
- Use `--safe-top/right/bottom/left` (set on `.app-root` in [src/App.css](src/App.css)) for overlays rather than raw `env()`.
- Handwriting font: Caveat via `@fontsource-variable/caveat`, bundled so it works offline; its `-ext` subsets are excluded from precache (`globIgnores` in vite.config.ts).
- Colors are tokens in [src/index.css](src/index.css) (desk, paper, paper-under/flap for the dog-ears, ink, fold), with dark-mode variants (dark desk, dimmed paper). `theme-color` and the manifest colors match the desk. `body` doesn't scroll (`overflow: hidden`) — only the canvas moves.

## PWA notes

- Configured in [vite.config.ts](vite.config.ts): `generateSW` mode, `registerType: 'prompt'`. The precache list is built from the hashed output, so there is NO manual cache-version bump — every build that changes files ships a new `sw.js`.
- [src/components/UpdatePrompt.tsx](src/components/UpdatePrompt.tsx) registers the SW via `useRegisterSW` (`virtual:pwa-register/react`, typed through [src/vite-env.d.ts](src/vite-env.d.ts)), shows the "offline ready" / "new version" banner, and polls `registration.update()` hourly for long-open installed apps. Updates never auto-reload — the user taps «Обновить», so an in-progress note is never lost to a reload.
- Manifest icons in `vite.config.ts` must match the files `npm run icons` writes to `public/`.
- The Claude desktop browser pane cannot register service workers at all; verify SW behavior in real Edge/Chrome (e.g. headless via playwright-core) against `npm run preview`.
