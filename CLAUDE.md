## Project Overview

A notes app as an installable, offline-capable PWA: React 19 + TypeScript + Vite 8. The PWA layer (Workbox service worker + web manifest) is generated by `vite-plugin-pwa`. Deployed via Cloudflare Workers Static Assets, same setup as the sibling project `C:\myGit\zuma-pwa`: every push to `main` of `github.com/ferZzz0/notes-pwa` triggers Cloudflare Workers Builds (`npm run build` + `npx wrangler deploy`, config in [wrangler.jsonc](wrangler.jsonc), serving `dist/` with SPA fallback). Production URL: https://notes-polik.sokolovpk.ru. UI text and code comments are in Russian.

**Cloudflare throttling in Russia (blank page).** The user's ISPs stall connections to Cloudflare's `188.114.96.1` / `188.114.97.1` after ~24 KB: the HTML loads, the JS bundle hangs in pending, the page stays blank. `104.21.46.231` / `172.67.143.35` work. Which pair a client gets is effectively random (checked 2026-10-25):

- The system resolver and Yandex `77.88.8.8` alternate between the good and the bad pair; Google `8.8.8.8` and Cloudflare DoH (browser "Secure DNS", which Chrome/Edge auto-enable when the system DNS is `1.1.1.1`) returned only the bad pair.
- `*.workers.dev` (incl. branch previews `*-notes-pwa.2004s-p.workers.dev`) always resolves to `188.114.x` — never verify there.

So any Russian visitor may randomly get a blank first load; once the SW has precached the app it starts from cache, and a failed update download retries later. Not fixable on the Cloudflare free plan; the real fix is hosting outside Cloudflare (e.g. Yandex Object Storage). **On 2026-10-25 the user decided to stay on Cloudflare for now** — don't re-propose migrating unless they ask or it blocks work.

To verify a deploy, pin a good IP instead of trusting DNS: `curl --resolve notes-polik.sokolovpk.ru:443:104.21.46.231 https://notes-polik.sokolovpk.ru/...`, or launch Edge/Chrome with `--host-resolver-rules="MAP notes-polik.sokolovpk.ru 104.21.46.231"`. A stall at ~24 KB means throttling, not a deploy bug.

## Workflow: always deploy

The user reviews every change on their phone (iPhone) against the deployed site, not locally. So after each finished change, without asking: run `npm run check` and `npm run build`, and if both pass, commit and push to `main` — Cloudflare deploys it. Never push a failing build. Then confirm the new version is live on https://notes-polik.sokolovpk.ru. Remind the user that the installed app picks it up via the «Доступна новая версия» → «Обновить» banner.

## UI

- **The product (user's decisions, 2026-10-25):** an open school notebook. The sheet ALWAYS fills the whole screen — status-bar/notch/home-indicator strips included; nothing but paper is ever visible, there is no desk and no «К началу листа» button (both removed at the user's request). A sheet is exactly ONE SCREEN at first (locked: it can't be panned or zoomed out, only zoomed in); when text comes near an edge, another whole screen of paper opens in that direction (down; outward to the side; never across the spine of a single page, never above the top). Portrait shows one page, landscape the spread; text can be written anywhere on the paper (double-tap), and a text is fully editable while and after writing it — a tap selects it (menu, no keyboard), another tap types; move with a finger, rotate/resize with two fingers (no handle buttons), colour from a colour wheel, font and letter effect from drop-down lists, marker presets on a written text, delete with confirmation; pages turn by curling up from the bottom outer corner. Plain paper — NO grid (the user asked to remove it: after a swipe the re-rasterized grid visibly redrew) and NO fold shadow along the spine (removed at the user's request; only the thin spine line remains in the spread). A gear (bottom centre) opens settings, which for now hold debug tools only: this build's time vs the server's, «Обновить» and «Стереть все данные». The manifest has no `orientation`.
- History, so it isn't retried blindly (all in git history): a «Поверните телефон» overlay; a "painted rotation" of the app in portrait (dropped: iOS keyboard/status bar don't rotate, iOS animates between painted and real landscape); portrait read-only / landscape write modes; a finite notebook with one textarea per 170×205 mm page, squared paper and double-tap zoom-to-page; truly infinite sheets with free flight (the user then asked for screen-sized sheets that grow); a 3D page flip (6 nested `preserve-3d` strips rotating around the spine, perspective `2·max(w, h)`) — in landscape the sheet is wider than tall, so the perspective was twice as strong as in portrait, the sheet's top/bottom edges left the screen and the turn read as a grey band sweeping across, then a dark page fading (the user: «очень криво») — replaced by the flat corner curl (`PageTurn`).
- **World coordinates:** `y = 0` is the top of the writing area (at home it sits at the top of the safe area; the paper continues above it under the status bar), the spine is `x = 0`; left page `x < 0`, right page `x ≥ 0`. Text sizes are in world px (Caveat 40px / 52px lines; other fonts in TextBlock.css).
- **[src/components/Canvas.tsx](src/components/Canvas.tsx)** — the pan/zoom engine, hand-written (no library) for full control over how gestures coexist with text input. Camera `{x, y, scale}` (screen = world·scale + x/y) is written straight to `.canvas-world`'s `transform` (no React re-render per frame). Generic: `home` (start view: `width` of world fills the safe-area width (scale ≥ `minScale`), world point `(x, y)` at the top of the safe area and at the centre / left / right edge per `align`), the sheet bounds (`content` rect, `fixed` edges, `bounded`, `extraBottom` — below), `locked`, `background` (screen-space layer under the world), `onFrame(cam, size)`/`onTap`/`onDoubleTap` callbacks and `grab` (a gesture whose first finger lands on something grabbable goes to it instead of the camera — `Grab` begin/move/end with 1–2 screen points) (all kept in a ref, so the once-subscribed listeners see fresh props), and a ref handle `goHome(home?, duration?)` (Promise; optional explicit target; resolves at once when the camera is already there), `visibleRect()`, `panBy()`.
  - **Sheet bounds** (`computeBounds`): the base is exactly the WHOLE screen at the `home` camera (inset strips included — home scale/position use the safe area, the paper doesn't). For every edge not in `fixed`, while `content` is within `EDGE_ZONE` (20%) of a screen from it, the edge moves out by a WHOLE screen (`steps()`), so sheets grow in screen-sized chunks. `extraBottom` (screen px; Notebook passes the open keyboard's height from `visualViewport`) temporarily lengthens the bottom so a line can be lifted above the keyboard. Clamping is hard: the sheet must cover the whole screen, min scale = "sheet covers the screen" (so an unextended sheet can't be zoomed out at all), max 2.5. `bounded={false}` lifts all of it (Notebook does that during transitions). When the bounds props change, `reclamp()` animates the camera back inside. Insets are measured in `measure()` (on resize and `goHome`), not per frame.
  - Gestures: one pointer drag = pan (after an 8px slop, so taps stay taps) with inertia on release (velocity of the last 100 ms, capped); two pointers = pinch around their midpoint + pan; wheel = pan, Ctrl/⌘+wheel (and Chrome's trackpad pinch) = zoom; Safari's Mac trackpad pinch comes only as `gesture*` events (ignored while touch pointers are active — on iOS they duplicate pointer events, we only `preventDefault` them). A single tap on non-interactive space blurs the focused field (closes the keyboard); a double tap there calls `onDoubleTap(worldPoint)`.
  - **After any resize/rotation the view is ALWAYS fully zoomed out** (user's request, 2026-10-25): `overviewCamera()` = the smallest scale at which the sheet still covers the screen (`minScale()`), top of the sheet, same horizontal anchor as `home`; applied on every ResizeObserver step (iPhone rotation resizes in several steps) and via the handle's `overview()`. Note a sheet grown only sideways can't zoom out further than home — its height still has to cover the screen. The very first layout is `home` (in `useLayoutEffect`, no flash).
  - `touch-action: none` on `.canvas` AND all descendants — otherwise a scrollable child (a textarea) claims the touch and the browser fires `pointercancel` mid-pan.
  - Pointer capture is taken only once a gesture becomes a pan/pinch, so a plain tap still focuses a textarea. Mouse presses on editable elements are ignored by the canvas (text selection works). Elements with `[data-no-pan]` are ignored entirely.
  - **Performance — the fix for the user's "lags with two fingers" (2026-10-25).** The world is ALWAYS its own compositor layer (`will-change: transform`), so pan/pinch only move/scale a ready bitmap. Camera writes are batched to one `transform` write per animation frame (pinch delivers a move per finger). After the camera settles (200 ms) and only if the scale changed, `settle()` drops/restores `will-change` once so text re-renders crisply. Chromium trace of a 120-move pinch: Paint 346 → 4, RasterTask 2083 → 20 (the old version changed a `--zoom` CSS variable every pinch frame, repainting the whole grid, and toggled the layer at every pause). Don't reintroduce per-frame style changes on the world or `will-change` toggling during gestures; keep big blurred shadows out of the world.
  - Safe-area insets are read from a hidden probe element (`env()` exists only in CSS).
- **[src/components/Paper.tsx](src/components/Paper.tsx)** — Canvas's `background`, in SCREEN space. Since the sheet always covers the screen, the paper itself is just the background colour (also on `.canvas` and `body`); the camera (via `onFrame`) only moves the full-height spine line (hidden for a single page, whose spine is the screen edge) — a `will-change` layer that only gets `transform` updates, nothing repaints. No fold shadow (the user removed it). Keep paper a plain colour: anything textured would have to be re-rasterized. (Earlier versions drew a desk around the sheet — removed.)
- **[src/components/Notebook.tsx](src/components/Notebook.tsx)** — spreads, writing, page turning, screen overlays:
  - Spread `s` (0-based) = pages `2s+1` | `2s+2`; state is the open PAGE (1-based). Only the current spread is rendered. Each side shows its page number by the spine; the date the spread was first written on (today's date faintly when empty) is on the right side, or on the left side when only it is shown; spread 0's left side has the help text. No staples (user removed them 2026-10-25).
  - **View by orientation (user's decision, 2026-10-25): portrait = ONE page, landscape = the spread** ([src/orientation.ts](src/orientation.ts) `usePortrait()`, `(orientation: portrait)`, desktops included). There is no setting for it (a gear with a «1 | 2» switch existed briefly — git history). One page = `display` `left`/`right`: `home` is that page's 850 world px filling the screen width with the spine on the screen edge (`align` right/left), and the spine edge is `fixed`. While moving between views (`transit`) both sides are drawn and the canvas is unbounded, so the camera can cross the spine without clamping jumps. The `single` state follows `portrait` one frame later via an effect, which then calls `canvas.overview()` (full zoom-out of the new view; flushSync can't run inside an effect, hence the frame). `Canvas.goHome()` re-measures the viewport itself, because the orientation media-query event fires BEFORE ResizeObserver delivers the new size (without that the new home was computed for the old screen).
  - **Content measuring:** after every render a layout effect measures all `.text-block`s on the visible sides (NOT the help note on page 1 — only what the user wrote grows a sheet; in landscape the help note reached the bottom zone and unlocked page 1) (`offsetLeft/Top/Width/Height` inside `.page-side` = world coords; `blockRect()` widens that by the text's rotation/scale, which TextBlock mirrors into `data-rotate`/`data-scale`) into `content` for the canvas. Font loading (`document.fonts` `loadingdone`/`ready`) triggers a re-render so the measure (and each TextBlock's auto-height) is redone — heights measured with the fallback font clipped the last lines of text on iPhone.
  - Left-page texts never cross the spine: created at most at x = −224 and wrapped at `min(640, −x − 24)` (≥ 200) (`maxWidthOf`). A text is as wide as its content (TextBlock measures it on a hidden mirror div — a textarea can't size itself to its text), at most that width.
  - **Writing:** double-tap on paper creates an empty [TextBlock](src/components/TextBlock.tsx) (it has 12/6 px padding (`BLEED_X/Y`) with matching negative margins so handwriting swashes aren't clipped by the textarea, text still at (x, y); content-width, auto-growing textarea, no chrome; colour (`--ink-color`)/font/rotation/scale from the block, rotation and scale around its centre; marker and shadow-type effects are drawn by a `.text-decor` div UNDER the textarea — same text, transparent letters, same box (fit() copies the size): the textarea's `overflow: hidden` would clip glows/shadows at its edge, and a highlighter must sit under the letters line by line (a `box-decoration-break: clone` span); the outline effect is on the textarea itself (`-webkit-text-stroke` + transparent fill); faces render the same in one div) at that point — with the last used colour and font (`notes-pwa:style`) — selects it and focuses it. The live textareas of the visible sides are ONE layer (`.page-texts`, world origin), not inside each `PageSide`, so a text moved across the spine stays the same element and keeps focus; `PageSide` renders texts only as static faces during a turn. It must be rendered with `flushSync` and focused synchronously inside the pointer handler — otherwise iOS won't open the keyboard. A text left empty is removed on blur. Double-tap above the writing area (`y < 0`, under the status bar) doesn't write — it just flies home. While a text is focused, `keepVisible` pans the camera so the line isn't hidden by the keyboard (uses `visualViewport`, on focus after 350 ms, on input, and on `visualViewport` resize) — unverified on a real iPhone.
  - **Editing a text (user's requests, 2026-10-25).** A tap on a text only SELECTS it (frame + toolbar, no keyboard); a tap on the selected text opens the keyboard (`edit()` focuses it inside the pointer handler — iOS needs that); a double tap on a text = both; a double tap on empty paper writes a new one. For that, textareas have `pointer-events: none` except the one being typed in (`.is-editing`), so taps reach the canvas, whose `onTap(worldPoint)` hit-tests the texts (`hitBlock`: rotation/scale-aware, +8 screen px). Moving/rotating/resizing has NO handles (the user removed them: «всё можно делать двумя пальцами»): a gesture whose first finger lands on the selected text (+16 px) is handed to `grab()` via Canvas's `grab` prop instead of moving the camera — one finger moves the text, two fingers also rotate (snaps to multiples of 90° within 4°) and resize it (0.4–4, snaps to 1) around the point between the fingers; a pinch starting on paper still zooms the sheet. `begin` re-bases on every finger-count change; patches don't save until `end` (`saveNow`). `place()` keeps the text below the top and wholly on the page its centre is on (one page view: on that page). [Selection](src/components/Selection.tsx) is just the dashed frame, in SCREEN space above the canvas, positioned from the textarea's offset box + rotation/scale + camera on every `onFrame` and after every render. [TextToolbar](src/components/TextToolbar.tsx) sits at the bottom (above the keyboard: `bottom = keyboard + 8`), one row even in portrait: a colour button (rainbow ring around the current colour) that opens a COLOUR WHEEL (user's request: «круговая палитра») — angle = hue, centre→edge = black→vivid, exactly `hsl(h, 100%, 50·r%)` (`wheelColor`/`wheelPosition` in [src/textStyle.ts](src/textStyle.ts); the CSS is a conic hue gradient under a black radial one), colour updates live while dragging and saves on release; a font DROP-DOWN (user's request; names shown in their own fonts — 6 fonts: Caveat, Marck Script, Pangolin bundled — Cyrillic+Latin subsets only; system sans/serif/mono); an effect drop-down (`EFFECTS`: glow, shadow, emboss, outline); a marker drop-down with presets (`MARKERS`: yellow/pink/green/blue highlighter, yellow/red underline, wavy underline) — shown only once the text isn't empty («на готовый текст»); delete — asks «Удалить надпись?» first; done. One menu at a time, opened above the toolbar, `max-height` = the room above it (little with the keyboard open — then it scrolls; the wheel shrinks). Its height is added to `extraBottom` and to `keepVisible`'s bottom limit. The toolbar `preventDefault`s `mousedown` so the textarea keeps focus. A tap on paper deselects; turning a page deselects. Arrows and gear are hidden while a text is selected (the toolbar takes the bottom).
  - **Settings** ([src/components/Settings.tsx](src/components/Settings.tsx)): light gear at the bottom centre between the arrows (top-right covered the page number/date in portrait); panel above it: this build's time (`__BUILD_TIME__`) and the server's (`/version.json`, fetched `no-store` on open — both from one `BUILD_TIME` in vite.config.ts, version.json isn't precached), whether a new version is already downloaded (`reg.waiting`); «Обновить» ([src/update.ts](src/update.ts) `updateNow`: `reg.update()` → wait for the installing worker (60 s timeout — Cloudflare throttling can stall it) → `SKIP_WAITING` → reload on `controllerchange`, or after 3 s if the page wasn't controlled; reports each step in the panel) — added because the user didn't see the update banner (2026-10-25); «Стереть все данные» with an inline confirmation → `clearAll()` + reload.
  - **Page turning:** round arrow buttons (chevron icons; deliberately light — translucent paper with backdrop blur and muted ink, in dark mode too) in the bottom screen corners (the update banner covers them — it is always on top of everything, user's request) (outside the canvas; no "back" on the first page/spread) or ←/→/PageUp/PageDown when not typing. Two pages: by spreads. One page: by pages — to the facing page of the same spread the camera simply flies across the spine; to another spread the sheet turns, then the camera follows to the new page's home. For a turn the camera first flies `home` (200 ms; instantly skipped when already there — the old unconditional 320 ms flight was the "delay before the turn" the user saw), then the half-sheet between the spine and the screen edge (world rect from `visibleRect()`) is turned by [PageTurn](src/components/PageTurn.tsx) (rAF-driven: 340 ms in the spread — the user first asked for 5× faster than the original 850 ms, then for half that speed; 850 ms on one page, where the camera then flies to the new page — the user decided to keep that one as is (2026-10-25); FLAT — clip-path + one `matrix()`, no 3D, so it looks the same at any aspect ratio and on iOS): the bottom outer corner travels through the spine to its mirror position along an arc lifted by `0.3·min(w, h)`; the fold line is the perpendicular bisector of the corner's start and current position. The part on the spine side (`.page-turn-front`: the page being turned on opaque paper) is clipped to the kept polygon; beyond the fold the underlay (destination's page on that side) shows, with a cast-shadow strip along the fold; the flap is the BACK page laid at its final position, clipped to the mirror (through the spine) of the turned polygon, and transformed by reflection-through-spine ∘ reflection-through-fold (a rotation; identity at the end, so it lands exactly). All turn layers are zero-size at world (0, 0) with world-coordinate contents and clip polygons. The turn's paper starts `spine/2` away from the spine (`spine` = 2 screen px in world units), so the spine line (Paper, under the world) is never covered — when the paper covered half of it, the line between the pages visibly thinned during the turn (the user: «место между листами становится меньше»). Gestures are `locked` during the turn. The underlay already shows the destination's sides, and everything is a static "face" during the turn (no textareas). The turn's end resolves its promise (`go()` is an async sequence using `flushSync` so Canvas sees new props before each `goHome`). `prefers-reduced-motion` makes the turn instant.

## PWA notes

- Configured in [vite.config.ts](vite.config.ts): `generateSW` mode, `registerType: 'prompt'`. The precache list is built from the hashed output, so there is NO manual cache-version bump — every build that changes files ships a new `sw.js`.
- [src/components/UpdatePrompt.tsx](src/components/UpdatePrompt.tsx) registers the SW via `useRegisterSW` (`virtual:pwa-register/react`, typed through [src/vite-env.d.ts](src/vite-env.d.ts)), shows the "offline ready" / "new version" banner (`z-index: 100` — ALWAYS above everything, the user asked for that), and calls `registration.update()` hourly AND whenever the page becomes visible again (`visibilitychange`) or the network comes back (`online`). The visibility check matters on iPhone: an installed app reopened from the home screen usually resumes from the background instead of relaunching, so the browser never checks for an update and iOS freezes the hourly timer — the user once saw no banner at all after a deploy. Updates never auto-reload — the user taps «Обновить», so an in-progress note is never lost to a reload; if the page isn't controlled by a SW yet (very first launch), the new SW has already activated without waiting, so «Обновить» just reloads. Why the banner may not show (user report, 2026-10-25): it appears only when the new SW finished installing while the app is open — the install can stall on throttled Cloudflare IPs (see above), and after a full close/reopen a downloaded version activates by itself with no banner. The settings' «Обновить» and the build/server times are the debugging aid for this.
- Manifest icons in `vite.config.ts` must match the files `npm run icons` writes to `public/`.
- The Claude desktop browser pane cannot register service workers at all; verify SW behavior in real Edge/Chrome (e.g. headless via playwright-core) against `npm run preview`.
