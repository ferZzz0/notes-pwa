## Project Overview

A notes app as an installable, offline-capable PWA: React 19 + TypeScript + Vite 8. The PWA layer (Workbox service worker + web manifest) is generated by `vite-plugin-pwa`. Deployed via Cloudflare Workers Static Assets, same setup as the sibling project `C:\myGit\zuma-pwa`: every push to `main` of `github.com/ferZzz0/notes-pwa` triggers Cloudflare Workers Builds (`npm run build` + `npx wrangler deploy`, config in [wrangler.jsonc](wrangler.jsonc), serving `dist/` with SPA fallback). Production URL: https://notes-polik.sokolovpk.ru. UI text and code comments are in Russian.

**Cloudflare throttling in Russia (blank page).** The user's ISPs stall connections to Cloudflare's `188.114.96.1` / `188.114.97.1` after ~24 KB: the HTML loads, the JS bundle hangs in pending, the page stays blank. `104.21.46.231` / `172.67.143.35` work. Which pair a client gets is effectively random (checked 2026-10-25):

- The system resolver and Yandex `77.88.8.8` alternate between the good and the bad pair; Google `8.8.8.8` and Cloudflare DoH (browser "Secure DNS", which Chrome/Edge auto-enable when the system DNS is `1.1.1.1`) returned only the bad pair.
- `*.workers.dev` (incl. branch previews `*-notes-pwa.2004s-p.workers.dev`) always resolves to `188.114.x` — never verify there.

So any Russian visitor may randomly get a blank first load; once the SW has precached the app it starts from cache, and a failed update download retries later. Not fixable on the Cloudflare free plan; the real fix is hosting outside Cloudflare (e.g. Yandex Object Storage). **On 2026-10-25 the user decided to stay on Cloudflare for now** — don't re-propose migrating unless they ask or it blocks work.

To verify a deploy, pin a good IP instead of trusting DNS: `curl --resolve notes-polik.sokolovpk.ru:443:104.21.46.231 https://notes-polik.sokolovpk.ru/...`, or launch Edge/Chrome with `--host-resolver-rules="MAP notes-polik.sokolovpk.ru 104.21.46.231"`. A stall at ~24 KB means throttling, not a deploy bug.

## Workflow: always deploy

The user reviews every change on their phone (iPhone) against the deployed site, not locally. So after each finished change, without asking: run `npm run check` and `npm run build`, and if both pass, commit and push to `main` — Cloudflare deploys it. Never push a failing build. Then confirm the new version is live on https://notes-polik.sokolovpk.ru. Remind the user that the installed app picks it up via the «Доступна новая версия» → «Обновить» banner.

## UI

- **Free navigation, same in every orientation (user's decision, 2026-10-25).** The notebook is an object on a desk and the user "flies" over it: pan, pinch-zoom, inertia, double-tap. Portrait and landscape behave identically — orientation only changes the window onto the same world; writing works everywhere. The manifest has no `orientation`.
- History, so it isn't retried blindly (all in git history): a «Поверните телефон» overlay; a "painted rotation" of the whole app in portrait (dropped: iOS keyboard/status bar don't rotate, iOS animates between painted and real landscape); portrait = read-only / landscape = write modes, with a stacked portrait layout (dropped for free navigation).
- **[src/components/Canvas.tsx](src/components/Canvas.tsx)** — the pan/zoom engine, hand-written (no library) for full control over how gestures coexist with text input. Camera `{x, y, scale}` (screen = world·scale + x/y) is written straight to `.canvas-world`'s `transform` (no React re-render per frame).
  - Gestures: one pointer drag = pan (after an 8px slop, so taps stay taps) with inertia on release (velocity of the last 100 ms, capped); two pointers = pinch around their midpoint + pan; wheel = pan, Ctrl/⌘+wheel (and Chrome's trackpad pinch) = zoom; Safari's Mac trackpad pinch comes only as `gesture*` events (ignored while touch pointers are active — on iOS they duplicate pointer events, we only `preventDefault` them). Double-tap on a `[data-zoom-target]` (the pages) zooms to it "fit width, top aligned" (in phone landscape a page already fills the height, so "fit whole" wouldn't zoom); again, or on the desk, shows the whole world.
  - Limits: zoom between half of "whole world fits" and 2.5 screen px per world px; at least 80px of the world always stays on screen. On resize/rotation the world point at the screen center stays centered; the very first layout fits the whole world (done in `useLayoutEffect`, so no unfitted flash).
  - `touch-action: none` on `.canvas` AND all descendants — otherwise a scrollable child (the note textarea) claims the touch and the browser fires `pointercancel` mid-pan. Consequence: the textarea can't be scrolled by touch or wheel (known limitation).
  - Pointer capture is taken only once a gesture becomes a pan/pinch, so a plain tap still focuses the textarea. Mouse presses on editable elements are ignored by the canvas (text selection works); double-tap on interactive elements (textarea, button…) doesn't zoom. Elements with `[data-no-pan]` (the page-turn corners) are ignored by the canvas entirely.
  - **Performance — the fix for the user's "lags with two fingers" (2026-10-25).** The world is ALWAYS its own compositor layer (`will-change: transform` in Canvas.css), so pan/pinch only move/scale a ready bitmap. Camera writes are batched to one `transform` write per animation frame (pinch delivers a move per finger). After the camera settles (200 ms without changes) and only if the scale changed, `rerasterize()` updates `--zoom` and drops/restores `will-change` once, so the layer re-renders crisply at the new scale. Measured with a Chromium trace during a 120-move pinch: Paint 346 → 5, RasterTask 2083 → 46. Don't reintroduce per-frame CSS-variable/style changes on the world or toggling `will-change` during gestures — the old version did both (`--zoom` every pinch frame repainted the whole grid; `.is-moving` toggled the layer at every pause), which is what lagged. Keep big blurred shadows inside the world small (they dominate raster cost).
  - The scale is exposed as `--zoom` on the world; the notebook uses `--hairline: calc(1px / var(--zoom))` so grid lines stay 1 screen px at any zoom (at "whole notebook" in portrait the scale is ~0.2 and 1px world lines vanished). It updates only on settle, so during a pinch lines scale with the bitmap.
  - Safe-area insets are read from a hidden probe element (`env()` exists only in CSS) and used when fitting.
- **[src/components/Notebook.tsx](src/components/Notebook.tsx)** — an infinite open school notebook as a fixed-size world object: a page is 170×205 mm (a real Russian school notebook) at 5 world px/mm → `PAGE_WIDTH` 850 × `PAGE_HEIGHT` 1025, grid cell `--cell` 25px (5 mm). Spread `s` (0-based) shows pages `2s+1` and `2s+2`; only the current spread is rendered, however many pages exist. No cover border, no red margin lines (user removed them 2026-10-25); fold shadow, spine, two staples, drop shadow on the desk.
  - **Page turning:** the dog-ear corner at a page's bottom outer edge (a `[data-no-pan]` button; none on page 1), or ←/→/PageUp/PageDown when not typing. The turning sheet is a `preserve-3d` div rotating 180° around the spine (`perspective` on `.notebook`), front = the page being turned, back (`rotateY(180deg)`, `backface-visibility: hidden`) = the page that lands on the other side, with a shading overlay. While it turns, the underlay already shows the destination spread's other page, and every page is a static "face" (no textarea → keyboard closes, no zoom targets). `animationend` on `.flip` itself commits the new spread. `prefers-reduced-motion` makes the turn instant.
  - [src/components/Page.tsx](src/components/Page.tsx) renders one page: page 1 is the title page (help text); others show the date first written on (school-style, today's date faintly on an empty page), the page number in the top outer corner, and the note textarea (or a plain div when `face`). Page text sizes/line-heights are multiples of `--cell` (keep it so); `.page` is a flex column so the note fills the page; pages are `width: 50%` so the spine sits exactly on the boundary. The note textarea re-enables `user-select` (the canvas disables it).
- **Storage** — [src/notes.ts](src/notes.ts): `localStorage` key `notes-pwa:pages` = `{ [pageNumber]: { text, created: 'YYYY-MM-DD' local } }`, only non-empty pages (clearing a page deletes it); `notes-pwa:spread` = the open spread, restored on launch. The old single note (`notes-pwa:draft`) is migrated to page 2 once. Saved on every keystroke. If notes grow large, move to IndexedDB; the installed iOS app has storage separate from Safari. Unverified on a real iPhone: how iOS scrolls/shifts the fixed, transformed canvas when the keyboard opens; a long note can't be scrolled within its page (touch-action), text past the page bottom is clipped.
- Use `--safe-top/right/bottom/left` (set on `.app-root` in [src/App.css](src/App.css)) for overlays rather than raw `env()`.
- Handwriting font: Caveat via `@fontsource-variable/caveat`, bundled so it works offline; its `-ext` subsets are excluded from precache (`globIgnores` in vite.config.ts).
- Colors are tokens in [src/index.css](src/index.css) (desk, paper, grid, ink, fold), with dark-mode variants (dark desk, dimmed paper). `theme-color` and the manifest colors match the desk. `body` doesn't scroll (`overflow: hidden`) — only the canvas moves.

## PWA notes

- Configured in [vite.config.ts](vite.config.ts): `generateSW` mode, `registerType: 'prompt'`. The precache list is built from the hashed output, so there is NO manual cache-version bump — every build that changes files ships a new `sw.js`.
- [src/components/UpdatePrompt.tsx](src/components/UpdatePrompt.tsx) registers the SW via `useRegisterSW` (`virtual:pwa-register/react`, typed through [src/vite-env.d.ts](src/vite-env.d.ts)), shows the "offline ready" / "new version" banner, and polls `registration.update()` hourly for long-open installed apps. Updates never auto-reload — the user taps «Обновить», so an in-progress note is never lost to a reload.
- Manifest icons in `vite.config.ts` must match the files `npm run icons` writes to `public/`.
- The Claude desktop browser pane cannot register service workers at all; verify SW behavior in real Edge/Chrome (e.g. headless via playwright-core) against `npm run preview`.
