## Project Overview

A notes app as an installable, offline-capable PWA: React 19 + TypeScript + Vite 8. The PWA layer (Workbox service worker + web manifest) is generated by `vite-plugin-pwa`. Hosted on **GitHub Pages**: every push to `main` of `github.com/ferZzz0/notes-pwa` runs [.github/workflows/pages.yml](.github/workflows/pages.yml) (`npm ci`, `npm run check`, `npm run build`, `dist/index.html` copied to `404.html`, deploy via `actions/deploy-pages`). Production URL: https://notes-polik.sokolovpk.ru — custom domain set in the repo's Settings → Pages; the DNS zone stays at Cloudflare with a CNAME `notes-polik` → `ferzzz0.github.io`, **DNS only (grey cloud)** — never proxied. UI text and code comments are in Russian.

**Why not Cloudflare (moved 2026-10-25, user's decision).** It used to be Cloudflare Workers Static Assets (like the sibling `C:\myGit\zuma-pwa`; [wrangler.jsonc](wrangler.jsonc) is left from that and can be deleted once the Worker is disconnected). Russian ISPs stall connections to Cloudflare's `188.114.96.x` / `188.114.97.x` after ~24 KB: the HTML loads, the JS bundle hangs, the page stays blank (and installed apps can't download updates). `104.21.46.231` / `172.67.143.35` worked, but which pair a client gets is a DNS lottery (on 2026-10-25 the system resolver and Google `8.8.8.8` returned the bad pair, Yandex `77.88.8.8` and `1.1.1.1` the good one; `*.workers.dev` always bad), and it isn't fixable on the free plan. GitHub Pages (`185.199.108–111.153`) was tested from the same Russian network: a 309 KB file in 0.6 s, no stall. Don't move the site back behind a Cloudflare proxy.

To verify a deploy: `curl -s https://notes-polik.sokolovpk.ru/version.json` shows the build time (also visible in the app's settings); `curl -sI` should show `server: GitHub.com`. The Pages deploy takes ~1–2 minutes after a push (Actions tab).

## Workflow: always deploy

The user reviews every change on their phone (iPhone) against the deployed site, not locally. So after each finished change, without asking: run `npm run check` and `npm run build`, and if both pass, commit and push to `main` — GitHub Actions deploys it to GitHub Pages. Never push a failing build. Then confirm the new version is live on https://notes-polik.sokolovpk.ru. Tell the user the installed app updates itself (it reloads into the new version as soon as it is idle or reopened — no banner any more).

## UI

- **The product (user's decisions, 2026-10-25):** an open school notebook. The sheet ALWAYS fills the whole screen — status-bar/notch/home-indicator strips included; nothing but paper is ever visible, there is no desk (removed at the user's request). A sheet is exactly ONE SCREEN at first (locked: it can't be panned or zoomed out, only zoomed in); when text comes near an edge, another whole screen of paper opens in that direction (down; outward to the side; never across the spine of a single page, never above the top). Portrait shows one page, landscape the spread; text can be written anywhere on the paper (double-tap), and a text is fully editable while and after writing it — a tap selects it (menu, no keyboard), another tap types; move with a finger, rotate/resize with two fingers (no handle buttons), colour from a colour wheel, font and letter effect from drop-down lists, marker presets on a written text, delete with confirmation; own photos (PNG too) and ready-made stickers to write on, both fully adjustable; pages turn by curling up from the bottom outer corner. Plain paper — NO grid (the user asked to remove it: after a swipe the re-rasterized grid visibly redrew) and NO fold shadow along the spine (removed at the user's request; only the thin spine line remains in the spread). There is a MAIN MENU (user's request, 2026-10-25) with several named diaries and a calendar — a date opens one sheet of notes for that day. New/empty sheets show ONLY the page number (no help text, no faint date — user's request). The bottom row (centre) is: undo, redo, «К началу листа» (a HOUSE icon — user's request; flies to `home` — start of the sheet, standard size), main menu, «+», gear. Pages turn by SWIPING the sheet sideways — there are no arrow buttons (user's request, 2026-10-25; ←/→ keys on a computer). - **[src/components/Canvas.tsx](src/components/Canvas.tsx)** — the pan/zoom engine, hand-written (no library) for full control over how gestures coexist with text input.   - **Sheet bounds** (`computeBounds`): the base is exactly the WHOLE screen at the `home` camera (inset strips included — home scale/position use the safe area, the paper doesn't). For every edge not in `fixed`, while `content` is within `EDGE_ZONE` (20%) of a screen from it, the edge moves out by a WHOLE screen (`steps()`), so sheets grow in screen-sized chunks. **The sheet keeps the screen's proportions** (user, 2026-10-26: «расширили по горизонтали — должен расшириться и по вертикали, и наоборот»): after the per-edge growth, the screens across and down are equalized to `n = max` of the two — extra width goes to the free side(s) (a spread: half to each, spine stays centred; one page: outward), extra height downward. So any grown sheet can be zoomed out to exactly 1/n — the short side no longer blocks zooming out. `extraBottom` (screen px) temporarily lengthens the bottom so a line can be lifted above the keyboard: Notebook passes the open keyboard's height from `visualViewport` (+ the toolbar's while something is selected), or `KEYBOARD_GUESS` (60% of the screen) for `TYPING_RESERVE_MS` = 1 s after `focusText()` (until the keyboard has opened — or it's a computer and none will), and NOTHING while only a toolbar is open without the keyboard (user: the sheet must not be movable down then). Clamping is hard: the sheet must cover the whole screen, min scale = "sheet covers the screen" (so an unextended sheet can't be zoomed out at all), max 2.5. `bounded={false}` lifts all of it (Notebook does that during transitions). When the bounds props change, `reclamp()` animates the camera back inside. Insets are measured in `measure()` (on resize and `goHome`), not per frame.

The very first layout is `home` too (in `useLayoutEffect`, no flash).

  - Pointer capture is taken only once a gesture becomes a pan/pinch, so a plain tap still focuses a text. Mouse presses on editable elements are ignored by the canvas (text selection works). Elements with `[data-no-pan]` are ignored entirely.

Camera writes are batched to one `transform` write per animation frame (pinch delivers a move per finger). After the camera settles (200 ms) and only if the scale changed, `settle()` drops/restores `will-change` once so text re-renders crisply. ## PWA notes

- Configured in [vite.config.ts](vite.config.ts): `generateSW` mode, `registerType: 'prompt'`. The precache list is built from the hashed output, so there is NO manual cache-version bump — every build that changes files ships a new `sw.js`.
- [src/components/UpdatePrompt.tsx](src/components/UpdatePrompt.tsx) registers the SW via `useRegisterSW` (`virtual:pwa-register/react`, typed through [src/vite-env.d.ts](src/vite-env.d.ts)), shows the "offline ready" banner (`z-index: 100` — ALWAYS above everything, the user asked for that), and calls `registration.update()` hourly AND whenever the page becomes visible again (`visibilitychange`) or the network comes back (`online`). The visibility check matters on iPhone: an installed app reopened from the home screen usually resumes from the background instead of relaunching, so the browser never checks for an update and iOS freezes the hourly timer — the user once saw no banner at all after a deploy. **Updates install THEMSELVES** (user, 2026-10-26: «обновления должны ставиться автоматически»; there is no «Доступна новая версия» banner any more): when `needRefresh` comes, `updateServiceWorker(true)` runs as soon as the app is idle — no focused editable, no pointer down, no `[role=dialog|alertdialog|toolbar]` on screen (`idle()`, re-checked every `BUSY_RETRY_MS` = 1.5 s) — or at once when the page goes hidden; notes are saved on every change and the open view/page is restored after the reload, so nothing is lost. If the page isn't controlled by a SW yet (very first launch), the new SW has already activated without waiting, so it just reloads. Why the banner may not show (user report, 2026-10-25): it appears only when the new SW finished installing while the app is open — the install can stall on throttled Cloudflare IPs (see above), and after a full close/reopen a downloaded version activates by itself with no banner. The debug section's «Обновить» and the build/server times are the debugging aid for this.
- Manifest icons in `vite.config.ts` must match the files `npm run icons` writes to `public/`.
- The Claude desktop browser pane cannot register service workers at all; verify SW behavior in real Edge/Chrome (e.g. headless via playwright-core) against `npm run preview`.
