## Project Overview

A notes app as an installable, offline-capable PWA: React 19 + TypeScript + Vite 8. The PWA layer (Workbox service worker + web manifest) is generated by `vite-plugin-pwa`. Hosted on **GitHub Pages**: every push to `main` of `github.com/ferZzz0/notes-pwa` runs [.github/workflows/pages.yml](.github/workflows/pages.yml) (`npm ci`, `npm run check`, `npm run build`, `dist/index.html` copied to `404.html`, deploy via `actions/deploy-pages`). Production URL: https://notes-polik.sokolovpk.ru — custom domain set in the repo's Settings → Pages; the DNS zone stays at Cloudflare with a CNAME `notes-polik` → `ferzzz0.github.io`, **DNS only (grey cloud)** — never proxied. UI text and code comments are in Russian.

**Why not Cloudflare (moved 2026-10-25, user's decision).** It used to be Cloudflare Workers Static Assets (like the sibling `C:\myGit\zuma-pwa`; [wrangler.jsonc](wrangler.jsonc) is left from that and can be deleted once the Worker is disconnected). Russian ISPs stall connections to Cloudflare's `188.114.96.x` / `188.114.97.x` after ~24 KB: the HTML loads, the JS bundle hangs, the page stays blank (and installed apps can't download updates). `104.21.46.231` / `172.67.143.35` worked, but which pair a client gets is a DNS lottery (on 2026-10-25 the system resolver and Google `8.8.8.8` returned the bad pair, Yandex `77.88.8.8` and `1.1.1.1` the good one; `*.workers.dev` always bad), and it isn't fixable on the free plan. GitHub Pages (`185.199.108–111.153`) was tested from the same Russian network: a 309 KB file in 0.6 s, no stall. Don't move the site back behind a Cloudflare proxy.

To verify a deploy: `curl -s https://notes-polik.sokolovpk.ru/version.json` shows the build time (also visible in the app's settings); `curl -sI` should show `server: GitHub.com`. The Pages deploy takes ~1–2 minutes after a push (Actions tab).

## Workflow: always deploy

The user reviews every change on their phone (iPhone) against the deployed site, not locally. So after each finished change, without asking: run `npm run check` and `npm run build`, and if both pass, commit and push to `main` — GitHub Actions deploys it to GitHub Pages. Never push a failing build. Then confirm the new version is live on https://notes-polik.sokolovpk.ru. Remind the user that the installed app picks it up via the «Доступна новая версия» → «Обновить» banner.

## UI

- **The product (user's decisions, 2026-10-25):** an open school notebook. The sheet ALWAYS fills the whole screen — status-bar/notch/home-indicator strips included; nothing but paper is ever visible, there is no desk and no «К началу листа» button (both removed at the user's request). A sheet is exactly ONE SCREEN at first (locked: it can't be panned or zoomed out, only zoomed in); when text comes near an edge, another whole screen of paper opens in that direction (down; outward to the side; never across the spine of a single page, never above the top). Portrait shows one page, landscape the spread; text can be written anywhere on the paper (double-tap), and a text is fully editable while and after writing it — a tap selects it (menu, no keyboard), another tap types; move with a finger, rotate/resize with two fingers (no handle buttons), colour from a colour wheel, font and letter effect from drop-down lists, marker presets on a written text, delete with confirmation; own photos (PNG too) and ready-made stickers to write on, both fully adjustable; pages turn by curling up from the bottom outer corner. Plain paper — NO grid (the user asked to remove it: after a swipe the re-rasterized grid visibly redrew) and NO fold shadow along the spine (removed at the user's request; only the thin spine line remains in the spread). There is a MAIN MENU (user's request, 2026-10-25) with several named diaries and a calendar — a date opens one sheet of notes for that day. New/empty sheets show ONLY the page number (no help text, no faint date — user's request). The bottom row (centre, between the page arrows) is: main menu, «+», gear. The gear opens settings, which for now hold debug tools only: this build's time vs the server's, «Обновить» and «Стереть все данные». The manifest has no `orientation`.
- History, so it isn't retried blindly (all in git history): a «Поверните телефон» overlay; a "painted rotation" of the app in portrait (dropped: iOS keyboard/status bar don't rotate, iOS animates between painted and real landscape); portrait read-only / landscape write modes; a finite notebook with one textarea per 170×205 mm page, squared paper and double-tap zoom-to-page; truly infinite sheets with free flight (the user then asked for screen-sized sheets that grow); a 3D page flip (6 nested `preserve-3d` strips rotating around the spine, perspective `2·max(w, h)`) — in landscape the sheet is wider than tall, so the perspective was twice as strong as in portrait, the sheet's top/bottom edges left the screen and the turn read as a grey band sweeping across, then a dark page fading (the user: «очень криво») — replaced by the flat corner curl (`PageTurn`).
- **World coordinates:** `y = 0` is the top of the writing area (at home it sits at the top of the safe area; the paper continues above it under the status bar), the spine is `x = 0`; left page `x < 0`, right page `x ≥ 0`. Text sizes are in world px (Caveat 40px / 52px lines; other fonts in TextBlock.css).
- **[src/components/Canvas.tsx](src/components/Canvas.tsx)** — the pan/zoom engine, hand-written (no library) for full control over how gestures coexist with text input. Camera `{x, y, scale}` (screen = world·scale + x/y) is written straight to `.canvas-world`'s `transform` (no React re-render per frame). Generic: `home` (start view: `width` of world fills the safe-area width (scale ≥ `minScale`), world point `(x, y)` at the top of the safe area and at the centre / left / right edge per `align`), the sheet bounds (`content` rect, `fixed` edges, `bounded`, `extraBottom` — below), `locked`, `background` (screen-space layer under the world), `onFrame(cam, size)`/`onTap`/`onDoubleTap` callbacks and `grab` (a gesture whose first finger lands on something grabbable goes to it instead of the camera — `Grab` begin/move/end with 1–2 screen points) (all kept in a ref, so the once-subscribed listeners see fresh props), and a ref handle `goHome(home?, duration?)` (Promise; optional explicit target; resolves at once when the camera is already there), `visibleRect()`, `panBy()`.
  - **Sheet bounds** (`computeBounds`): the base is exactly the WHOLE screen at the `home` camera (inset strips included — home scale/position use the safe area, the paper doesn't). For every edge not in `fixed`, while `content` is within `EDGE_ZONE` (20%) of a screen from it, the edge moves out by a WHOLE screen (`steps()`), so sheets grow in screen-sized chunks. `extraBottom` (screen px; Notebook passes the open keyboard's height from `visualViewport`) temporarily lengthens the bottom so a line can be lifted above the keyboard. Clamping is hard: the sheet must cover the whole screen, min scale = "sheet covers the screen" (so an unextended sheet can't be zoomed out at all), max 2.5. `bounded={false}` lifts all of it (Notebook does that during transitions). When the bounds props change, `reclamp()` animates the camera back inside. Insets are measured in `measure()` (on resize and `goHome`), not per frame.
  - Gestures: one pointer drag = pan (after an 8px slop, so taps stay taps) with inertia on release (velocity of the last 100 ms, capped); two pointers = pinch around their midpoint + pan; wheel = pan, Ctrl/⌘+wheel (and Chrome's trackpad pinch) = zoom; Safari's Mac trackpad pinch comes only as `gesture*` events (ignored while touch pointers are active — on iOS they duplicate pointer events, we only `preventDefault` them). A single tap on non-interactive space blurs the focused field (closes the keyboard); a double tap there calls `onDoubleTap(worldPoint)`.
  - **After any resize/rotation the view is ALWAYS the standard `home` view** — the start of the sheet at the standard size, however it was zoomed and however far the sheet has grown (user's request, 2026-10-25; it was "fully zoomed out" before, which made a sheet grown sideways smaller than standard); applied on every ResizeObserver step (iPhone rotation resizes in several steps) and via the handle's `showHome()`. The very first layout is `home` too (in `useLayoutEffect`, no flash).
  - `touch-action: none` on `.canvas` AND all descendants — otherwise a scrollable child (a textarea) claims the touch and the browser fires `pointercancel` mid-pan.
  - Pointer capture is taken only once a gesture becomes a pan/pinch, so a plain tap still focuses a textarea. Mouse presses on editable elements are ignored by the canvas (text selection works). Elements with `[data-no-pan]` are ignored entirely.
  - **Performance — the fix for the user's "lags with two fingers" (2026-10-25).** The world is ALWAYS its own compositor layer (`will-change: transform`), so pan/pinch only move/scale a ready bitmap. Camera writes are batched to one `transform` write per animation frame (pinch delivers a move per finger). After the camera settles (200 ms) and only if the scale changed, `settle()` drops/restores `will-change` once so text re-renders crisply. Chromium trace of a 120-move pinch: Paint 346 → 4, RasterTask 2083 → 20 (the old version changed a `--zoom` CSS variable every pinch frame, repainting the whole grid, and toggled the layer at every pause). Don't reintroduce per-frame style changes on the world or `will-change` toggling during gestures; keep big blurred shadows out of the world.
  - Safe-area insets are read from a hidden probe element (`env()` exists only in CSS).
- **[src/components/Paper.tsx](src/components/Paper.tsx)** — Canvas's `background`, in SCREEN space. Since the sheet always covers the screen, the paper itself is just the background colour (also on `.canvas` and `body`); the camera (via `onFrame`) only moves the full-height spine line (hidden for a single page, whose spine is the screen edge) — a `will-change` layer that only gets `transform` updates, nothing repaints. No fold shadow (the user removed it). Keep paper a plain colour: anything textured would have to be re-rasterized. (Earlier versions drew a desk around the sheet — removed.)

Used on 2026-10-25 at the user's explicit request to wipe all (test) notes everywhere; to wipe again, change `RESET_ID` — only when the user asks, it's irreversible. Add any new storage key to `ALL_KEYS` — `clearAll()` (the settings' «Стереть все данные») wipes those keys but keeps the reset marker.

## PWA notes

- Configured in [vite.config.ts](vite.config.ts): `generateSW` mode, `registerType: 'prompt'`. The precache list is built from the hashed output, so there is NO manual cache-version bump — every build that changes files ships a new `sw.js`.
- [src/components/UpdatePrompt.tsx](src/components/UpdatePrompt.tsx) registers the SW via `useRegisterSW` (`virtual:pwa-register/react`, typed through [src/vite-env.d.ts](src/vite-env.d.ts)), shows the "offline ready" / "new version" banner (`z-index: 100` — ALWAYS above everything, the user asked for that), and calls `registration.update()` hourly AND whenever the page becomes visible again (`visibilitychange`) or the network comes back (`online`). The visibility check matters on iPhone: an installed app reopened from the home screen usually resumes from the background instead of relaunching, so the browser never checks for an update and iOS freezes the hourly timer — the user once saw no banner at all after a deploy. Updates never auto-reload — the user taps «Обновить», so an in-progress note is never lost to a reload; if the page isn't controlled by a SW yet (very first launch), the new SW has already activated without waiting, so «Обновить» just reloads. Why the banner may not show (user report, 2026-10-25): it appears only when the new SW finished installing while the app is open — the install can stall on throttled Cloudflare IPs (see above), and after a full close/reopen a downloaded version activates by itself with no banner. The settings' «Обновить» and the build/server times are the debugging aid for this.
- Manifest icons in `vite.config.ts` must match the files `npm run icons` writes to `public/`.
- The Claude desktop browser pane cannot register service workers at all; verify SW behavior in real Edge/Chrome (e.g. headless via playwright-core) against `npm run preview`.
