## Project Overview

A notes app as an installable, offline-capable PWA: React 19 + TypeScript + Vite 8. The PWA layer (Workbox service worker + web manifest) is generated by `vite-plugin-pwa`. Deployed via Cloudflare Workers Static Assets, same setup as the sibling project `C:\myGit\zuma-pwa`: every push to `main` of `github.com/ferZzz0/notes-pwa` triggers Cloudflare Workers Builds (`npm run build` + `npx wrangler deploy`, config in [wrangler.jsonc](wrangler.jsonc), serving `dist/` with SPA fallback). Production URL: https://notes-polik.sokolovpk.ru. UI text and code comments are in Russian.

**Cloudflare throttling in Russia (blank page).** The user's ISPs stall connections to some Cloudflare addresses after ~24 KB: the HTML loads, the JS bundle hangs in pending, the page stays blank. Which address a client gets depends on DNS:

- ISP / Yandex plain DNS → `104.21.46.231`, `172.67.143.35` — works.
- Cloudflare and Google DNS-over-HTTPS (browser "Secure DNS", which Chrome/Edge auto-enable when the system DNS is `1.1.1.1`; Android Private DNS) → `188.114.96.1`, `188.114.97.1` — stalls.
- `*.workers.dev` (incl. branch previews `*-notes-pwa.2004s-p.workers.dev`) resolves to `188.114.x` even over plain DNS — never verify deploys there.

Not fixable on the Cloudflare free plan. User-side fix: turn off the browser's Secure DNS (or pick "use current service provider") and fully restart the browser. To diagnose, check DevTools → Remote Address, or test each IP: `curl --resolve notes-polik.sokolovpk.ru:443:<ip> https://notes-polik.sokolovpk.ru/assets/<bundle>.js` — a stall at ~24 KB means throttling, not a deploy bug.

## Workflow: always deploy

The user reviews every change on their phone (iPhone) against the deployed site, not locally. So after each finished change, without asking: run `npm run check` and `npm run build`, and if both pass, commit and push to `main` — Cloudflare deploys it. Never push a failing build. Then confirm the new version is live on https://notes-polik.sokolovpk.ru. Remind the user that the installed app picks it up via the «Доступна новая версия» → «Обновить» banner.

## Commands

```powershell
npm install
npm run dev        # Vite dev server with HMR at http://localhost:5173 (service worker disabled)
npm run check      # type-check only (tsc --noEmit, TypeScript 7); Vite itself does not type-check
npm run build      # production build into dist/ (also emits sw.js + manifest.webmanifest)
npm run preview    # serve dist/ at http://localhost:4173 — the place to test offline/update behavior
npm run icons      # regenerate PNG icons + favicon.ico from public/icon.svg (pwa-assets.config.ts)
```

There are no tests yet.

## UI

- **Landscape only.** The manifest sets `orientation: 'landscape'`, which only an installed Android PWA honors; iOS ignores it and offers no web API to lock orientation, so [src/components/RotateHint.tsx](src/components/RotateHint.tsx) covers the whole UI under `(orientation: portrait) and (pointer: coarse)`. Narrow desktop windows are deliberately not covered. Don't design portrait layouts.
- **Main screen = open school notebook** ([src/components/Notebook.tsx](src/components/Notebook.tsx), takes `left`/`right` page content; the content itself lives in [src/App.tsx](src/App.tsx)). Squared paper, red margin lines on the OUTER edge of each page, fold shadow and two staples on the spine, cover peeking out around the pages.
- Sizing uses container query units: `.notebook-scene` (full screen minus safe-area insets) is a size container, and the spread is clamped between A5 proportions (1.41:1) and 1.75:1 so phones in landscape don't waste the sides. `.notebook` is itself a size container, so the grid cell `--cell: clamp(12px, 100cqh / 30, 22px)` on `.page` follows the notebook height. Page text sizes and line-heights are multiples of `--cell` so text sits on the grid — keep it that way, and only use `--cell` inside `.page` (its cq units resolve against the nearest container).
- Handwriting font: Caveat via `@fontsource-variable/caveat`, bundled so it works offline; its `-ext` subsets are excluded from precache (`globIgnores` in vite.config.ts).
- Colors are tokens in [src/index.css](src/index.css) (desk, cover, paper, grid, margin line, ink, fold), with dark-mode variants (dark desk, dimmed paper). `body` doesn't scroll (`overflow: hidden`) — scrolling, when needed, belongs inside pages.

## PWA notes

- Configured in [vite.config.ts](vite.config.ts): `generateSW` mode, `registerType: 'prompt'`. The precache list is built from the hashed output, so there is NO manual cache-version bump — every build that changes files ships a new `sw.js`.
- [src/components/UpdatePrompt.tsx](src/components/UpdatePrompt.tsx) registers the SW via `useRegisterSW` (`virtual:pwa-register/react`, typed through [src/vite-env.d.ts](src/vite-env.d.ts)), shows the "offline ready" / "new version" banner, and polls `registration.update()` hourly for long-open installed apps. Updates never auto-reload — the user taps «Обновить», so an in-progress note is never lost to a reload.
- Manifest icons in `vite.config.ts` must match the files `npm run icons` writes to `public/`.
- The Claude desktop browser pane cannot register service workers at all; verify SW behavior in real Edge/Chrome (e.g. headless via playwright-core) against `npm run preview`.
